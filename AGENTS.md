## Hard constraints
- React Native + Expo, Custom Dev Client, EAS Build only.
- NEVER hand-edit android/ or ios/ — they are gitignored and generated by `expo prebuild` on EAS. All native config goes through Expo Config Plugins in app.config.js / plugins/, and custom native code goes in modules/ (Expo Modules API).
- Any time a native dependency is added or changed, stop and flag it — don't attempt a local native build. Tell the user (or run, if you have terminal access and eas is authenticated) `eas build --profile development --platform android`.
- Follow the folder structure in docs/3_File_Directory_Structure.md exactly. Don't invent new top-level folders.
- Stack: Zustand (state), react-native-gesture-handler + react-native-reanimated (gestures), drizzle-orm + expo-sqlite (storage), react-native-vlc-media-player (media engine), react-native-track-player (background audio), OpenSubtitles API (subtitles).
- License: GPLv3. No ads, no analytics/tracking SDKs, no paid-tier code paths — the product is free end to end.

## Working style
- Work through docs/5_AI_Coding_Prompts.md one prompt at a time, in order. Don't skip ahead to a later phase.
- Before writing code for a prompt, briefly restate what you're about to do and which files you'll touch.
- After each prompt: summarize what changed, note any deviation from the docs and why, and stop for review before starting the next prompt.
- If a library's actual current API doesn't match what a doc assumes, say so and propose the adjustment — don't silently improvise around it.
- Commit after each prompt is accepted, with a message referencing the prompt number (e.g. `feat: Prompt 1.3 - Zustand player store`).

## Source of truth for conflicts
If something in these instructions conflicts with docs/1-5, the docs win — this file is a summary/reminder, not a replacement.
